# Миграция на новые версии

Исходная база образа: gramps-web-api `v3.7.1.1`, фронтенд `grampsjs:26.2.0`, Gramps 6.0, Debian Bookworm.

Статус: шаг на `v3.12.2` + `grampsjs:26.4.3` применён.

Анализ актуален на 2026-11-03 (последние версии: gramps-web-api `v3.25.1`, gramps-web `v26.11.0`).

## Рекомендуемый следующий шаг

**gramps-web-api `v3.12.2` + фронтенд `grampsjs:26.4.3`**

- нет новых миграций БД пользователей;
- Gramps остаётся 6.0.x;
- оба патча из `patches/` накладываются без изменений.

Изменения в `Dockerfile`:

```dockerfile
# builder
ARG GRAMPS_WEB_API_VERSION=v3.12.2
# runtime (версия пакета из _version.py)
ARG GRAMPS_WEB_API_VERSION=3.12.2
# frontend
COPY --from=ghcr.io/gramps-project/grampsjs:26.4.3 /usr/share/nginx/html /static
```

## Переход дальше v3.12

- **Миграции.** `docker-entrypoint.sh` при старте выполняет `user migrate`, БД обновится автоматически. Откат на старый образ после этого невозможен — перед обновлением сделать бэкап `/app/users`.
- **v3.21.1+.** Патч `0001_media_import` нужно переписать: в `media_importer.py` теперь три вызова `zipfile.ZipFile(...)`, upstream `metadata_encoding` так и не добавил, проблема с не-ASCII именами в zip остаётся.
- **v3.24+.** Требуется Python ≥ 3.11 (в Bookworm — 3.11, ок).
- **v3.25+.**
  - Патч `0002_pygobject_version` не накладывается: на строке `PYGObject<=3.50.0` добавлен комментарий `# keep in sync with Dockerfile.base`.
  - Из `pyproject.toml` убраны extras `ai`/`all` — сверить с тем, как AI отключается в `Dockerfile`.

Промежуточный вариант без переписывания патчей: **v3.21.0 + `grampsjs:26.8.1`** (с 4 новыми миграциями).
